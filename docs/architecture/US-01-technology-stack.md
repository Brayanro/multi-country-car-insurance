# US-01 — Technology stack proposal

**Status** Human approved on 2026-11-22 ([approval record](../approvals/US-01-architecture-approval.md))  
**Scope** US-01 architecture and the shared foundations for US-02 and US-03  
**Basis** [US-01 Draft 3](../../spec/US-01.md) and the technical assessment, pp. 1–3 and 6–9

## Recommendation and compatibility

Recommend the proposed stack with Angular **21.x LTS**, Strapi **5.x**, and a common patched **Node.js 24 LTS** line. Angular 21 allows Node 24 and TypeScript 5.9.x. Strapi 5 documents support for Node 24 and SQLite 3, and Playwright and pnpm 11 support the same Node line. Pin current compatible patches and the Node container version when scaffolding. Angular workspace packages, the Angular CLI, and Angular ESLint use the same major. Strapi can retain its own tested TypeScript toolchain, with the shared contract kept compatible with both consumers. Angular 22 is an upgrade option with a longer support horizon and TypeScript 6 requirements. Angular 21 LTS provides the requested capabilities with a smaller compatibility surface for this assessment. Review an upgrade before its LTS ends if the app continues beyond the assessment. [Angular compatibility](https://angular.dev/reference/versions), [Angular release support](https://angular.dev/reference/releases), [Strapi prerequisites](https://docs.strapi.io/cms/quick-start), [Node release lines](https://nodejs.org/en/about/previous-releases), [Playwright installation](https://playwright.dev/docs/intro), [pnpm 11 release notes](https://pnpm.io/blog/releases/11.0)

## Proposed startup and verification

- Organize the workspace under `frontend/` and `backend/`, with a smallest-necessary TypeScript workspace contract shared by both and an isolated Playwright suite. Use one browser origin. Strapi remains a private Compose service for app traffic, with a separate loopback admin binding for local editorial review. Static hosting serves Angular's deep-link fallback and proxies only the dedicated content reader URLs. Generate or inject Strapi-only startup secrets locally without putting them in the repository or browser. Admin provisioning is separate from the public app's readiness.
- Target `docker compose up --build` on a clean checkout. Use a one-time, idempotent seed step for published CO and CL forms and the minimum custom Public permission. Seed through server-side Strapi facilities. Verify readiness from this initialization and HTTP listener health while preserving usability if an editor unpublishes a country form later. Record initialization completion in the CMS volume so restart preserves editorial changes and deliberately removed entries. Use fictitious fixtures and avoid a pre-seeded admin password. US-02 and US-03 extend the seed with plan and term content in their own approved increments.
- In US-01 verification, cover decoder, validation, and reconciliation units, integrated route races, behavior through the same-origin proxy, and a real Strapi publication change consumed after reload without rebuilding Angular. Verify public access to the one intended reader, anonymous denial of other endpoints, draft exclusion, duplicate/empty/malformed configuration recovery, country isolation, keyboard and mobile/desktop usability, and clean-tree startup plus restart with preserved edits. Check native SQLite loaded in the runtime container and exact resolved package compatibility before treating the stack as verified.
- Full-flow Playwright coverage waits until US-02 and US-03 are implemented under their own checkpoints. Verify a complete simulated quote for at least one country and smoke the other, using both countries' seed data. Later verification covers country currency, active/published plans, plan selection, terms revision, masked summary, payment failure and retry, and duplicate protection. The US-01 step-transition test does not require an implemented plans UI.

## Review choices

Approve the stack and [country/content](../adr/ADR-001-multi-country-content.md), [dynamic form](../adr/ADR-002-dynamic-form-contract.md), and [wizard state](../adr/ADR-003-frontend-quote-state.md) proposals together or request changes to individual items. The defaults proposed for human review are exact uppercase country normalization, session storage for same-tab reload retention, an allowed bounded pattern subset, March 1 treatment of leap-day birthdays in non-leap years, and the restriction on defaults for required selects. If older browser versions must be supported beyond the stated intersection, provide the target versions before implementation. Pricing inputs, final plan and terms contracts, and simulated payment reload/receipt policy are decisions for the applicable later stories.
