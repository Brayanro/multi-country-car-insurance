# US-02 — Plan List

**Status:** Draft 1 · Human approved  
**Source:** `requirements/technical-assessment.pdf`, pages 2–3 and 7  
**Related story:** US-02 — Plan list  
**Dependencies:** Approved US-01 and ADR-001, ADR-002, ADR-003

## Objective

As a person getting a quote, I want to compare the plans available for my country, their prices and coverages, and choose one plan that fits my needs.

The plans step uses the active country and validated policyholder and vehicle data from US-01. It displays eligible published plan content in the order configured in Strapi, formats prices for the country, distinguishes a recommended plan, and allows one plan to be chosen for the US-03 summary handoff.

## Scope and dependencies

### In scope

- Read plans for the active country from Strapi and show only plans that are both published and active, in configured order.
- Display each plan's configured name, short description, price, coverages and benefits. Format its price using the country's currency and format.
- Distinguish a recommended plan from the user's selected plan. Recommendation alone does not select a plan.
- Allow exactly one plan selection and keep that selection with the active country's quote so it can be handed to US-03.
- Show an explanatory empty state when no eligible plans exist.
- Provide accessible loading and recoverable error states with retry. Do not show another country's plans or stale plans as current.
- Support keyboard operation and mobile and desktop layouts, consistent with the approved shared design system.

### Dependencies on US-01

- The user must have completed US-01 with a valid form for the country in the URL before entering plans. Invalid or incomplete form data cannot reach plans.
- Returning to US-01 retains its values. Any plan price adjustment that depends on those values must use the current validated data.
- The country URL and country-isolated browser quote state follow approved ADR-001 and ADR-003.

### Out of scope

- US-03 owns the summary content, terms, and payment. US-02 verifies its selection through an observable same-country route or narrow screen handoff seam. The complete quote flow is project-level verification after US-03 exists.
- Real underwriting, rating, or payment services. Use fictitious data and a documented deterministic simulation only if the price question below is resolved in favor of an adjustment.
- Editorial workflows beyond publishing plan content in Strapi.

## Functional acceptance criteria

### AC-US02-01 — Country eligibility and configured order

**Given** valid US-01 data exists for the country in the URL and Strapi contains plans for both countries, including draft or inactive plans  
**When** the user opens the plans step  
**Then** only published, active plans for that country are shown  
**And** they appear in their configured order  
**And** a plan change published in Strapi is reflected after the plans content is reloaded without a frontend code change or redeployment.

### AC-US02-02 — Plan details and price

**Given** eligible plans are configured for the active country  
**When** the user compares plans  
**Then** each plan shows its configured name, short description, coverages, and benefits  
**And** its price is shown using the country's currency and format  
**And** the displayed final price follows the resolved pricing rule in Q-US02-01.

### AC-US02-03 — Recommendation and chosen state

**Given** one eligible plan is marked recommended  
**When** the user views the plans  
**Then** that plan is visually identified as recommended  
**And** recommendation is distinguishable from the user's chosen state  
**And** no plan is selected solely because it is recommended.

### AC-US02-04 — Single plan selection and handoff

**Given** the user is viewing eligible plans  
**When** the user chooses a plan  
**Then** that plan is identified as chosen  
**And** choosing another plan replaces the prior choice so only one remains chosen  
**And** the chosen plan and its displayed final price are available to the active country's quote state  
**And** Continue is available only when plan content is ready and the user has explicitly selected a currently eligible plan with a current price based on the current valid US-01 data  
**And** before the first explicit choice, while content is loading or unavailable, or while eligibility and price are being revalidated, the user cannot continue  
**And** a same-country route or narrow screen seam makes the US-03 handoff observable  
**And** US-03 owns the summary content.

### AC-US02-05 — No eligible plans

**Given** the country has no published active plans  
**When** the user opens the plans step  
**Then** an explanatory empty state is shown  
**And** no plan can be selected or submitted  
**And** the user can return to US-01.

### AC-US02-06 — Loading and retrieval failure

**Given** plan content is loading or the request fails  
**When** the plans step is opened or retried  
**Then** an accessible loading status or recoverable error with retry is shown, as applicable  
**And** the user cannot continue without an eligible selected plan  
**And** data and selection are not read from another country's quote  
**And** failed or superseded content is not presented as current  
**And** a refresh, unavailable response, changed US-01 data, or changed plan catalog cannot allow a stale price or an ineligible choice to proceed  
**And** the exact restoration or invalidation policy for a still-eligible selection is defined at the architecture checkpoint.

### AC-US02-07 — Keyboard and responsive use

**Given** the plans step is used on mobile or desktop  
**When** the user navigates and selects using only the keyboard  
**Then** every plan choice has an accessible name and selected state  
**And** the recommendation and price are available with that choice  
**And** the step remains usable at both viewport sizes.

## Existing architecture and implementation seam

- Approved ADR-001 defines the URL country boundary, Strapi published-content read boundary, and a future country-specific Plan collection. It leaves the exact plan shape, public read action, and price rules to this story's architecture stage.
- Approved ADR-003 assigns quote state to the frontend and anticipates a single selected plan reference plus a calculated price snapshot. It leaves selection invalidation and price snapshot details to later rules.
- ADR-002 defines the US-01 form contract. It does not define the plan DTO or runtime validation contract.
- The approved design system and plan concept wireframes specify a native radio choice, separate recommended and selected indicators, and nearby price, coverage, and benefit content. See `docs/design/US-01-design-system.md` and `docs/design/US-01-wireframes.md`.
- The current Angular route and quote state support the US-01 handoff to `/plans`, but the plans view is still a placeholder. No plan collection, plan read endpoint, plan DTO, or plan selection state exists yet.

### Architecture items for the next checkpoint

The approved decisions give direction but not a complete plan contract. After this specification is approved, the architect should define the Strapi Plan schema and public read projection, country and publication filtering, order and stable plan identity, bounded runtime validation and error codes, and how the selection and price snapshot integrate with ADR-003. The architect should decide whether this belongs in a new ADR or an amendment to ADR-001/ADR-003. The approved public-read boundary still applies: no browser write token and only the minimum public read permission.

## Question and proposal

| ID | Status | Question or proposal |
|---|---|---|
| Q-US02-01 | Resolved by Draft 1 approval | The assessment permits a simulated final-price adjustment based on US-01 data but gives no inputs, formula, rounding rule, or display explanation. Is an adjustment required for this increment? **Proposal:** use base price as final price unless a deterministic rule is explicitly approved. If adjustment is required, specify its inputs, formula, rounding, and any explanation shown with the price before approval. |

## Boundaries

- **Always:** Use only the active country's published, active Strapi plans; display the configured order and country currency; keep quote and plan selection in frontend country-scoped state; use fictitious data; preserve accessible keyboard and responsive behavior.
- **Ask first:** Change the approved country or quote-state boundaries, add a dependency, or change this approved specification or a later approved architecture decision.
- **Never:** Expose a Strapi write-privileged token in the browser, use real customer/payment data, or integrate real rating or payment services.
