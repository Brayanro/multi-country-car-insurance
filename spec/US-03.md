# US-03 — Summary and payment

**Status:** Draft 2 · Approved by the project owner on 2026-11-22

**Source:** [Technical assessment](../requirements/technical-assessment.pdf), pages 2–3 and 8–9

**Related story:** US-03 — Summary and payment

**Dependencies:** [US-01](US-01.md), [US-02](US-02.md), [ADR-001](../docs/adr/ADR-001-multi-country-content.md), [ADR-002](../docs/adr/ADR-002-dynamic-form-contract.md), [ADR-003](../docs/adr/ADR-003-frontend-quote-state.md) and [ADR-004](../docs/adr/ADR-004-plan-catalog-and-selection.md)

## Objective

As a person who chose a plan, I want to review my quote and complete a simulated payment so that I can see confirmation of the quote.

US-03 consumes the active country's current, validated Details data and the explicitly selected plan with its final price. It adds the country-specific Strapi terms, consent and simulated payment result to the existing quote flow.

## Scope and dependencies

### In scope

- Show the current entered policyholder and vehicle values with their configured labels, plus the selected plan and its final price.
- Partially mask the identity document in the summary using the same rule in both countries, including its accessible presentation.
- Read the terms configured in Strapi for the active country. Before each Pay action, refresh the terms. Require acceptance of the terms currently presented and bind acceptance to their revision and the current quote snapshot.
- Allow a person to return to edit Details or change the plan within the same country. Retain valid saved values and selection under the approved US-01 and US-02 rules.
- Simulate successful and rejected payment outcomes using fictitious quote data only. A demo-only accessible outcome selector defaults to Approved and can select Rejected deterministically. Use one Pay action, block duplicate submissions while processing, and show one simulated quote number for a successful quote.
- On simulated failure, show a clear error and allow retry with the quote information retained.
- After reload, make an interrupted simulation retryable. Preserve a completed receipt and block another payment for the completed quote.
- Provide recoverable terms loading or retrieval failure states, keyboard operation, accessible labels/status, and usable mobile and desktop layouts.

### Dependencies on US-01 and US-02

- Summary requires valid current Details data for the country in the URL and a current, explicitly chosen eligible plan. Direct or history navigation cannot bypass these prerequisites. Reuse the US-02 fresh catalog validation before exposing Summary.
- The selected plan's configured base price is its final price under the approved US-02 decision. Use the country currency and formatting already defined there.
- Use each current form field's configured label and stable purpose metadata. Locate the document by `identityDocument` purpose, not by its label. Exclude values removed from the current form configuration.
- Same-country Back navigation retains the Details draft and plan candidate according to ADR-003 and ADR-004. Editing a field invalidates consent for the prior quote snapshot. The plan remains selected only under US-02's eligibility and price revalidation rule.

### Out of scope

- Real payment gateways, card collection, underwriting, quote persistence on a server, or cross-device payment deduplication.
- Changing the approved country boundary, form contract, plan contract, or final-price rule.
- Any new visual direction. Use the approved design system and existing wizard conventions when this story reaches design or implementation.

## Functional acceptance criteria

### AC-US03-01 — Current quote summary

**Given** valid Details data and a currently eligible plan are present for the country in the URL

**When** the person reaches Summary

**Then** the summary shows entered policyholder and vehicle values using the current configured labels

**And** it shows the explicitly selected plan and its final price in that country's currency

**And** it excludes values discarded from the current form configuration

**And** it does not expose data from another country's quote.

### AC-US03-02 — Shared document masking rule

**Given** the current form has a field with `identityDocument` purpose and it has a value

**When** the summary is displayed or its accessible content is read

**Then** the same masking rule applies in Colombia and Chile, revealing at most the last four alphanumeric characters for longer values

**And** for values with two to four alphanumeric characters only the final character is revealed, with separators preserved

**And** a one-character value is fully masked

**And** its complete value is not exposed in the summary's visible or accessible presentation.

### AC-US03-03 — Country terms and consent

**Given** the person reaches Summary for Colombia or Chile

**When** the terms are loaded

**Then** the displayed text is the Strapi terms returned for that country

**And** payment is unavailable until the person accepts the displayed terms

**And** acceptance applies only to that terms revision and the current quote snapshot

**And** before each eligible Pay attempt, the app refreshes the terms from Strapi for the active country

**And** if that read returns the accepted revision and the quote snapshot is unchanged, payment may proceed

**And** if the read returns a changed revision, the updated text is presented and payment is blocked until the person reviews and accepts the new terms for the current quote snapshot.

### AC-US03-04 — Edit and change plan

**Given** the person is reviewing a quote

**When** they return to Details or Plans

**Then** they return within the same country

**And** the saved Details and eligible plan selection are retained according to US-01 and US-02 rules

**And** after any change, Summary uses the current validated values and current eligible plan price

**And** consent for a previous quote snapshot is not reused.

### AC-US03-05 — Successful simulated payment

**Given** the terms refresh returned the accepted revision and consent is current for the quote snapshot

**When** the person uses the single Pay action with the demo-only outcome set to Approved

**Then** the submission is locked while the simulation is processing

**And** repeated activation does not start another attempt

**And** success displays a confirmation with one simulated quote number for that quote

**And** submitting again for the completed quote does not start another attempt

**And** the demo-only outcome selector is accessible and defaults to Approved.

### AC-US03-06 — Rejected simulated payment and retry

**Given** the terms refresh returned the accepted revision and consent is current for the quote snapshot

**When** the person sets the demo-only outcome to Rejected and uses the single Pay action

**Then** the person sees a clear error

**And** their Details, selected plan, current terms and quote information remain available

**And** the Details, selected plan and quote are retained for retry in both countries

**And** they can retry without starting a second concurrent attempt

**And** they can set the demo-only outcome to Approved and use the same Pay action for the retry

**And** a later successful attempt shows one quote number for the completed quote.

### AC-US03-07 — Reload and completed receipt

**Given** the payment simulation is processing or has completed

**When** the page is reloaded

**Then** an interrupted simulation becomes retryable without losing the Details or selected plan

**And** a completed quote restores the same confirmation receipt

**And** another payment for that completed quote remains blocked.

### AC-US03-08 — Details and plan prerequisites

**Given** Details are invalid or missing, or the plan is absent or no longer eligible

**When** the person opens Summary

**Then** the wizard returns them to the earliest applicable prerequisite step in the same country

**And** the Summary does not present stale plan or price data

### AC-US03-09 — Recoverable terms failure

**Given** current Details and plan prerequisites are valid but country terms are loading, empty, invalid or unavailable, including an unavailable pre-Pay refresh

**When** the person views Summary or attempts payment

**Then** the summary remains available with a clear terms status and recovery action

**And** payment remains blocked until valid current terms are ready and accepted

**And** no data or terms from the other country are used

**And** recovery retains the Details draft and plan candidate.

### AC-US03-10 — Keyboard and responsive use

**Given** Summary and payment are used with a keyboard on mobile or desktop

**When** the person reviews the summary, accepts terms, returns to edit, or submits payment

**Then** all actions have accessible names and visible focus

**And** loading, processing, failure and success status is available to assistive technology

**And** the flow remains usable at mobile and desktop viewport sizes.

## Existing architecture and implementation seam

- ADR-001 and ADR-003 establish the URL country boundary, frontend-only country-scoped quote state, tab-scoped recovery and no server persistence of quote or payment data.
- ADR-003 already specifies identity-document masking by stable `identityDocument` purpose, consent bound to the current terms revision and quote snapshot, an atomic processing state for duplicate protection, one confirmation number per successful quote and retry after reported failure. This draft resolves its reserved reload behavior: interrupted payment is retryable and completed receipt is preserved with duplicate payment blocked.
- ADR-004 establishes a fresh same-country plan catalog check before Summary and the selected plan's base price as final price.
- The current Angular wizard has a `/summary` handoff after Details and plan revalidation. Summary is still a placeholder. The shared form contract contains `identityDocument` purpose metadata and the plan contract contains final `basePrice` data. The current Strapi content projection serves forms and plans; it has no terms content or terms read contract. No Summary terms or payment behavior exists yet.
- The exact Strapi terms shape and minimal public read permission, typed runtime contract, terms revision identifier and integration point in the existing quote state remain for the architecture checkpoint after this specification is approved. The specified behavior requires terms to refresh before Pay, blocks payment if that refresh fails, and requires fresh acceptance if the returned revision changed.

## Boundaries

- **Always:** Use the active country's current quote state; show a partially masked identity document; require current terms consent; keep payment simulated; retain quote information through a reported failure; and prevent duplicate attempts.
- **Ask first:** Change the approved country or quote-state boundaries, or change this specification after approval or a later approved architecture decision.
- **Never:** Expose a Strapi write-privileged token in the browser, send quote data to Strapi, use real customer or card data, or integrate a real payment service.
